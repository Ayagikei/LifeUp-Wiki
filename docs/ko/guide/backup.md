# 백업 및 복원

> [!IMPORTANT]
> LifeUp은 오프라인 우선 App입니다. 대부분의 개인 데이터는 기기에 저장됩니다. 백업을 설정하지 않으면 App 삭제, 기기 변경, 기기 손상 시 데이터가 영구적으로 손실될 수 있습니다.

## 1) 백업이 중요한 이유 :id=why-backup

### 어떤 위험을 대비하나요?

대부분의 사용자는 다음 상황에서 데이터를 잃습니다.

1. App 삭제(기본 백업 경로의 파일은 시스템 정리로 제거될 수 있음)
2. 백업 파일을 옮기지 않은 채 기기 변경
3. 기기 손상/분실

안정적인 백업이란 데이터가 같은 휴대폰에만 있는 것이 아니라 다른 기기나 저장 매체에도 존재한다는 뜻입니다.

### 백업에 포함되는 항목은?

백업에는 작업, 속성, 상점 데이터, 업적, 감정, 뽀모도로 기록, 설정 등 로컬 핵심 데이터가 포함됩니다. 미디어 파일(첨부 파일, 아이콘, 배경, 오디오)도 포함할 수 있습니다.

> [!TIP]
> 백업 크기가 10MB를 넘으면 "미디어/사진 파일 무시"를 켜거나 백업 간격을 늘리면 안정성이 좋아집니다.

## 2) 백업 방법 설정 :id=configure-methods

대부분의 영어권 사용자에게는 다음 우선순위가 가장 잘 맞습니다.

| 방법 | 추천 | 적합한 용도 | 자동 백업 | 참고 |
| --- | --- | --- | --- | --- |
| Google Drive | ⭐⭐⭐⭐⭐ | 일상 사용, 간편한 클라우드 동기화 | 예 | App에서 원탭 인증 |
| Dropbox | ⭐⭐⭐⭐ | 일상 사용, 기기 간 동기화 | 예 | App 내 인증도 지원 |
| 로컬 내보내기(사용자 지정 경로) | ⭐⭐⭐⭐ | PC / NAS로 수동 복사 | 아니오(수동) | 안정적인 대안 및 버전별 아카이브 |
| WebDAV | ⭐⭐⭐ | 셀프 호스팅 / 기존 WebDAV 서비스 | 예 | 이미 WebDAV를 쓰는 경우 좋은 대안 |
| Download 폴더 자동 백업(Android 10+) | ⭐⭐⭐ | 삭제로 인한 손실 위험 감소 | 예 | 기기 손상에는 대비하지 못함 |

<details>
<summary>Google Drive / Dropbox 자동 백업 설정(권장)</summary>

App에서 다음으로 이동합니다.
`사이드바 → 설정 → 데이터 백업/복원/삭제`

그다음:

1. Google Drive 또는 Dropbox 인증
2. "클라우드 백업 구성"에서 방법 선택
3. "자동 클라우드 백업 사용" 활성화
4. "자동 백업 간격" 설정
5. 필요 시 "미디어/사진 파일 무시" 활성화

</details>

<details>
<summary>WebDAV 클라우드 백업 설정(선택)</summary>

WebDAV 호환 서비스를 사용하는 경우:

1. `WebDAV 구성` 열기
2. URL, 계정, 비밀번호 입력
3. 연결 테스트 실행
4. 클라우드 백업 방법으로 WebDAV 사용

</details>

<details>
<summary>사용자 지정 경로로 내보내기(수동 대안)</summary>

수동으로 휴대 가능한 백업을 원할 때 사용합니다.

1. `백업` 탭
2. `사용자 지정 경로` 선택
3. 생성된 파일 저장(보통 `.lfbak`)
4. PC / NAS / 클라우드 저장소로 복사

> [!WARNING]
> 유일한 백업을 같은 휴대폰에만 두지 마세요.

</details>

## 3) 백업 방법 :id=how-to-backup

<details>
<summary>일상 자동 백업 워크플로 실행</summary>

1. 클라우드 설정 하나 완료(Google Drive 또는 Dropbox)
2. 자동 클라우드 백업 및 간격 활성화
3. 한 번 수동 백업을 실행해 정상 동작 확인
4. "마지막 백업" 안내를 주기적으로 확인

</details>

<details>
<summary>중요 변경 전 수동 백업 실행</summary>

다음 작업 전에 추가 로컬 내보내기를 만듭니다.

- 주요 App 업데이트
- 시스템 초기화/재플래시
- 기기 변경

사용: `백업 → 사용자 지정 경로`, 그다음 파일을 외부 저장소로 복사.

</details>

## 4) 복원 방법 :id=how-to-restore

<details>
<summary>클라우드 백업에서 복원(Google Drive / Dropbox / WebDAV)</summary>

1. 대상 기기에서 동일한 클라우드 계정/방법 구성
2. `복원` 탭 후 해당 방법 선택
3. 복원 확인(App이 재시작됨)

> [!WARNING]
> 복원은 현재 로컬 데이터를 덮어씁니다. 현재 데이터가 중요하면 먼저 로컬 백업을 내보내세요.

</details>

<details>
<summary>로컬 백업 파일에서 복원</summary>

1. 백업 파일을 대상 기기로 이동
2. `복원 → 사용자 지정 경로` 탭
3. 백업 파일 선택 후 확인

"파일 시스템에서 백업 파일 열기 지원"을 켜면 파일 관리자나 공유 App에서 직접 가져올 수도 있습니다.

> [!TIP]
> 읽기/쓰기 오류로 복원에 실패하면 다른 파일 경로를 시도하고 파일을 다시 선택해 보세요.

</details>

### 새 기기로 이전 :id=phone-migration

<details>
<summary>새 휴대폰으로 이전(시스템 또는 백업 경로)</summary>

#### 옵션 A: 내장 휴대폰 이전 기능 우선 사용

일부 휴대폰은 전체 App 데이터 이전을 지원합니다(제조사 이전 도구 / 시스템 복제).

1. 구 휴대폰에서 신 휴대폰으로 시스템 이전 실행.
2. LifeUp을 열고 핵심 데이터(작업, 속성, 상점 데이터, 업적) 확인.
3. 이전이 정상으로 보여도 신 휴대폰에서 새 백업을 하나 만드세요.

#### 옵션 B: 클라우드 백업 또는 백업 파일로 이전(범용)

1. 구 휴대폰에서 먼저 새 백업 생성.
2. 신 휴대폰에 LifeUp 설치.
3. 클라우드 이전: 동일한 클라우드 방법/계정 구성 후 복원.
4. 파일 이전: 백업 파일 전송 후 `복원 → 사용자 지정 경로` 사용.
5. 복원 후 수동 백업을 한 번 실행해 신 휴대폰의 백업 체인 확인.

> [!WARNING]
> 복원은 로컬 데이터를 덮어씁니다. 신 휴대폰에 이미 중요한 새 항목이 있으면 먼저 내보내세요.

</details>

## 5) 자주 묻는 문제 :id=common-issues

<details>
<summary>복원 오류 수정: 유효하지 않은 백업 파일</summary>

- 파일이 LifeUp에서 생성된 것인지 확인.
- `.lfbak`이 권장 형식입니다.

</details>

<details>
<summary>복원 오류 수정: 더 높은 백업 버전 파일</summary>

LifeUp을 최신 버전으로 업데이트한 뒤 다시 복원하세요.

</details>

<details>
<summary>느리거나 불안정한 클라우드 백업 개선</summary>

- "미디어/사진 파일 무시" 활성화.
- 자동 백업 간격 늘리기.
- 백업 전 사용하지 않는 미디어 파일 정리.

</details>

<details>
<summary>Download 폴더 자동 백업만으로 충분한지 판단</summary>

- 삭제 관련 손실에는 도움이 됩니다.
- 기기 손상/분실에는 대비하지 못합니다.
- 더 안전한 전략: 클라우드 백업 + 주기적 로컬 내보내기 병행.

</details>
