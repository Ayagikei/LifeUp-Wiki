# 개발 로드맵

*LifeUp*은 현재 여가 시간에 유지보수되며 자원이 제한적이므로 개발 계획이 정확히 실행된다고 보장하지 않으며 특정 출시 시점을 약속하지 않습니다.

<br/>

## 업데이트 전략

로컬 기능의 업데이트 주기는 14–21일 이내를 유지합니다.

각 기능 업데이트 후 여러 수정 버전을 출시할 수 있습니다.

World 모듈 기능은 양단 공동 개발, 요구사항 동기화, 서버 배포, 서버 성능 제한, 호환성 등 여러 요인이 관련됩니다.

개발 주기는 로컬 기능보다 길며, 주로 신규 기능 도입보다 유지보수에 집중합니다.



**업데이트 우선순위(대략):**

충돌 버그 수정 >> 신규 사용자에 영향을 주는 경험 버그 수정 >> 기능 업데이트 > UI 및 세부 버그 수정.

<br/>

## 버전 번호 전략

`1.80.3`과 같은 세 자리 버전 번호를 사용합니다.

**첫 번째 자리**(예: **1**.80.3)는 App의 주요 개정에 사용되는 버전 번호이며, 1은 초기 정식 버전입니다. 개선 시 코드 리팩터링/UI 재설계 변경이 많이 포함될 수 있습니다.


**중간 자리**(예: 1.**80**.3)는 기능 버전 번호(feature)입니다. 중간 수준 기능이 출시되거나 상대적으로 많은 소규모 기능이 누적되면 버전 번호가 올라갑니다.

예:

> 버전 64에서 상점·창고·보관 시스템 출시.
>
> 버전 70에서 Simple Mode 출시.
>
> 버전 80에서 개봉(언박싱) 시스템 출시.



**세 번째 자리**(예: 1.80.**3**)는 각 기능 출시 후 일부 문제/충돌을 수정하는 개정 번호입니다. 동시에 소규모 기능도 포함될 수 있습니다.


> 구버전은 1.58c와 같이 영문자로 표현된 세 자리 버전 번호도 사용했습니다.
>
> 기본 전략은 위와 같지만 세 번째 구간이 영문자이며 `a`부터 시작합니다.
>
> 일부 App 마켓에서 이 버전 번호 전략을 지원하지 않아 현재는 사용하지 않습니다.
