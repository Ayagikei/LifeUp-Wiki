要約：

1. 以前確立した方向性を実行：安定性と既存機能の最適化を重視し、新機能モジュールを恣意的に追加しない。
2. 1〜2 のメジャーバージョンで、基本機能の欠陥とペインポイントを解決。
3. その後、カレンダー連携と繰り返し型実績に着手。
4. API などを継続的に改善。

マルチプラットフォームは 2024 年の重要目標の一つ。

### II. 2023 年振り返り

LifeUp の半分アマチュア・半分余暇の開発の旅は 5 周年を迎え、6 年目に入りました。Android リポジトリだけでも数百バージョンをリリースし、約 5000 回のコードコミットを重ねてきました。

<br/>

2022 年 10 月に提案した開発計画は LifeUp 機能体系の深化を目指していましたが、環境の変化により、道のりには多くの障害とトラブルもありました。

#### 1.1 環境

典型的な例：

- 一部の省で「反詐欺」誤報告の影響を受け、申立てチャネルがなく、数ラウンドかけて一部問題を解決。しかし最近また山東省で誤報問題が発生し、申立てや再現経路をまだ見つけられていない。
- 中国国内 Android App 市場の審査基準が層を重ねて厳格化、市場間・担当者間で基準が不一致、審査担当者の非専門性。
  - 一部 App 市場は変更のない部分で審査拒否することが多い。
  - ある V App 市場は「プライバシーコンプライアンス」を理由に LifeUp App の審査拒否をほぼ行った。市場は App に [すべてのファイル読み取り権限] または [すべての写真読み取り権限] の申請と対応説明を要求し、ユーザーがアルバムから画像を選択できるようにした。しかし LifeUp はよりプライバシー保護的なアプローチを採用し、そのような権限は不要で、ユーザーファイルを直接読み取らない。代わりに App はシステム組み込みのアルバム App に遷移し、ユーザーが選択した画像のみを受け取り、最大限のプライバシー保護を確保。
    しかし審査担当者はこのベストプラクティスに馴染みがなく、カスタマーサポートとの数日間のやり取りでようやく承認された。

<br/>

環境の影響を減らすため：

App 内アップデート機構を強化し、市場審査提出の頻度を減らしました。

国内版は App 内アップデートに対応し、安定版またはベータチャネルを切り替え可能。

![Screenshot_2023-12-09-15-45-33-18_50eeeb96828cbaa](_media/development_plan_2024/Screenshot_2023-12-09-15-45-33-18_50eeeb96828cbaa.jpg)

公式サイト（https://lifeupapp.fun/en/index.html）も代替ダウンロードチャネルとして更新。

![image-20231209154445462](_media/development_plan_2024/image-20231209154445462.png)

市場審査のリスクと遅延を避け、皆さんが Web サイト経由で App をダウンロード・インストールしやすくするため。

App 内ネットワークリクエストにもバックアップチャネルを追加し、一部省での誤報によるアクセス問題を緩和・防止。

<br/>

審査基準がますます厳しくなり、国内 Android 市場で他のインディー開発者が遭遇するさまざまな障害を目の当たりにして、

インディー開発者にとって、国内 Android プラットフォームはもはや理想的な第一選択のローンチ先ではないと言える。

結局、国内 Android には最も厳しい資格要件と、最も複雑で **変化しやすい** 審査基準がある。

> 皮肉なことに、同時に、低品質なコピー App が簡単に上架し「手動再審査合格」と表示されることもある。

これが、小紅書で見かける多くのインディー開発者作品が iOS 版のみである理由かもしれない。

Google Play と App Store が第一選択のまま。

?> 国内 Android プラットフォームに粘り続けるインディー開発者や小規模チームにも、ぜひ注目と支援をお願いします~

<br/>

2024 年は：

- 前計画の未完了部分（カレンダー連携、繰り返し型実績、基本機能、データシステムなど）をこの期間に移行。
- マルチプラットフォーム開発が重要目標、おそらく 2 方向：
  - Flutter で LifeUp を複製（人手限定のため、バックエンド担当の Xiao Xiao が推進）
  - KMP（Kotlin Multiplatform）でより多くの可能性を探索

#### 1.2 国内ユーザー成長

加えて、LifeUp は 2023 年に中国 App 市場でも大きなユーザー成長を遂げました。皆さんのサポートに感謝！

- 引き換えコード手動発行の時間を減らし、開発により集中するため：2023 年に自動決済（WeChat、Alipay）を追加接続し、WeChat ログインに対応。
  - これにより多くの時間を解放。

- 2023 年、Qzone でのユーザー拡散により、再びサーバーが数日間ダウン。
- WeChat 公式アカウント、小紅書、Bilibili などの運用も試し、LifeUp のアップデートと創造的な使い方を紹介・宣伝。

- 他のインディー開発者との議論で、多くが同様の困難を経験し、最終的に特定の IM や SNS チャネルを閉鎖することを選んだことがわかった。深く共感。
  - 大企業には通常、専用カスタマーサポートチームやボットがあり、大量の問い合わせを処理し、開発者向けの具体的なニーズや問題フィードバックに変換できる。
  - **しかしインディー開発者は一般にカスタマーサポートと運用を一人で担い、理不尽なユーザー対応がこのインディー開発者の開発時間の 100% を消費し、最終的に開発者、製品、製品のコアユーザーに影響する。**
  - したがって、メールなどでのフィードバック提供をますます推奨。

<br/>

2024 年は：

- 反復的な相談業務への人的投入を継続的に削減し、代わりにドキュメントと FAQ を改善。相談があっても、メール、QQ チャネルなどで統一対応。
- 少量の SNS 運用を試行。

LifeUp は買い切り App のため、ユーザー成長は非常に重要で、継続運営と将来フルタイム開発のチャンスの礎。

#### 1.4 品質管理

LifeUp は一人で開発・テストするオフラインツール App のため、深刻なクラッシュ問題の回避が特に重要。

2023 年のバージョン反復プロセスは以前より長く、ベータテストに十分な時間を確保し、万全の準備を図った。

![image-20231209154314651](_media/development_plan_2024/image-20231209154314651.png)

これらの措置は、大規模な深刻クラッシュの発生を効果的に防止しているよう。

しかし、各バージョンアップデートには依然として問題が伴い、クリティカルパス上のものも含まれる。

したがって、LifeUp の品質管理を継続改善し、安定性を最重要指標とする（環境と審査の厳しさが増す中で特に）。

<br/>

2024 年は：

- 品質管理を強化。

#### 1.5 機能の深化

3 周年記事で述べたように、LifeUp は段階的に探索・成長した App。

ショップ、カスタム実績、API などの機能は当初計画になく、アップデートとフィードバックに伴い段階的に開発・追加された。

しかしこれにより問題も生じた：

- 一部モジュールの計画詳細が粗い。
  - 例：アイテム報酬は当初単一報酬のみを想定。
  - 属性などのシステムも当初カスタマイズを想定せず、段階的リファクタリングでのみ追加／削除やカスタムレベルなどに対応。
  - 属性報酬／ペナルティポップアップと履歴表示が最大 3 つまでなど、このような問題が多い。
- 新規追加モジュールは App 全体の分析・計画が不足。

3 周年記事で述べた方向を継続し、既存機能モジュールを深化し、ペインポイントを解決。新機能モジュールの追求ではない。

例：アイテム報酬の直接複数選択対応、バックアップ機構改善、通知最適化、ウィジェット完成など。

#### 1.6 API と拡張性

上述の通り、新機能モジュールの導入は計画しない。

しかし App を拡張する需要は必ずある。

2023 年に API 機能を導入。

LifeUp のコアを基盤能力として提供。

プログラミングがわからなくても、Tasker/MacroDroid などの自動化ツールで機能拡張し、自動化能力を実現可能。

典型例：

- NFC、QR コードでタスク完了
- 起床時の自動チェックイン
- カスタムウィジェット
- など...

プログラミングがわかれば、さらに多くのゲームプレイや App まで拡張可能。

![img](_media/development_plan_2024/desktop.png)

API に基づくシンプルなデスクトップ版も開発（オープンソース）。

数バージョンの API 拡張後も、依然として多くの能力が不足。

例：「思考」関連操作未対応、Content Provider 経由のデータ更新未対応など。

2024 年も API を継続拡張し、App のあらゆる側面を可能な限りカバー。

> 現在多くのユーザーが API を個人利用しているが、共有可能な実行製品は依然少数。API エコシステム構築のため、より強力な API 能力の提供を継続する必要がある。

#### 1.7 未来について

上記の問題と環境変化に伴い、LifeUp の生涯メンバーシップ価格も段階的に調整（それでも LifeUp のメンバーシップ価格は他 App の大多数よりはるかに低い）。アップデートも段階的にメンバーシップ機能として提供する方向へ。

App は最終的にコアユーザーに奉仕することを徐々に認識。

コアユーザーのフィードバックとサポートが App 改善に反映され、開発者とユーザーの共創と好循環を実現。

全員を喜ばせようとすると、App はコードのごちゃ混ぜになり、コアユーザーの要求から逸脱し、開発者の収益とモチベーションを低下させる。

<br/>

上記で KMP（Kotlin Multiplatform）に言及。比較的新興のクロスプラットフォーム技術。ネイティブ能力の混合利用も可能。

LifeUp 開発中、いくつかの新しいアイデアが段階的に生まれた。しかしすべてのアイデアが LifeUp に実装できる、または適しているわけではない。

例：UI 全体の置き換え、ショップロジックの大幅変更など、既存ユーザー体験に深刻な影響を避けられない。大規模 App 変更による失敗事例も多く見てきた。

<br/>

また、LifeUp 初期開発時、公式 DB フレームワーク「Room」はまだ利用不可で、国内ニッチ DB フレームワークを選択。

現在パフォーマンス問題が顕在化し、置き換えが困難。

加えて、LifeUp は Material 3 とレガシー Material Design の両方、ダークモード、多言語、国内端末システムの断片化（互換性設定ドキュメントはますます長く、ネイティブシステムと海外版は一般に単一ページ設定で済む）などに対応。各ページで多くの複雑なことを考慮する必要がある。

<br/>

KMP を探索し、KMP で使える技術があるか検証する計画。

将来、より多くのアイデアと新プロジェクトを実装するチャンスも——スキルは多いほど損はない。
