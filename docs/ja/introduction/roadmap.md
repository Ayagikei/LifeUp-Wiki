# 開発ロードマップ

*LifeUp* は現在、余暇時間でのメンテナンスでありリソースが限られているため、開発計画が正確に実行されることを保証せず、具体的なリリース時期も約束しません。

<br/>

## アップデート戦略

ローカル機能のアップデートサイクルは 14〜21 日以内を維持します。

各機能アップデート後、いくつかの修正版をリリースする場合があります。

World モジュールの機能は、両端共同開発、要件同期、サーバーデプロイ、サーバーパフォーマンス制限、互換性など複数の要因を伴うため、

開発サイクルはローカル機能より長く、新機能の導入よりもメンテナンスが中心になります。



**アップデート優先度（おおよそ）：**

クラッシュバグ修正 >> 新規ユーザーに影響する体験バグ修正 >> 機能アップデート > UI と細部のバグ修正。

<br/>

## バージョン番号戦略

3 桁のバージョン番号を使用します。例：`1.80.3`。

**最初の桁**（例：**1**.80.3）はアプリケーションの大規模改訂に使用するバージョン番号で、1 は初期正式版です。改善に伴い、大規模なコードリファクタリング/UI 再設計が行われる場合があります。


**中間の桁**（例：1.**80**.3）は機能バージョン番号（feature）です。中規模の機能がリリースされたり、比較的多くの小規模機能が蓄積されたりすると増加します。

例：

> バージョン 64 でショップ&ストア&倉庫システムをリリース。
>
> バージョン 70 でシンプルモードをリリース。
>
> バージョン 80 で開封システムをリリース。



**3 桁目**（例：1.80.**3**）は、各機能リリースの問題/クラッシュ修正のためのリビジョン番号です。同時に、小規模な機能を追加する場合もあります。


> 旧バージョンでは英字で表す 3 桁バージョン番号（例：1.58c）も使用していました。
>
> 基本戦略は上記と同じですが、3 桁目が英字となり `a` から始まります。
>
> 一部のアプリマーケットがこのバージョン番号戦略をサポートしていないため、現在は廃止しています。
