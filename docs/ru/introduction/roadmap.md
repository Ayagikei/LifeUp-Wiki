# Дорожная карта разработки

Поскольку *LifeUp* сейчас поддерживается в свободное время и с ограниченными ресурсами, мы не гарантируем точное выполнение плана разработки и не обещаем конкретные сроки выхода.

<br/>

## Стратегия обновлений

Цикл обновлений локальных функций останется в пределах 14–21 дня.

После каждого обновления функций мы можем выпускать несколько исправлений.

Поскольку модуль «Мир» связан с несколькими факторами — совместная разработка на двух платформах, синхронизация требований, развёртывание сервера, ограничения производительности сервера и совместимость —

цикл разработки будет длиннее, чем у локальных функций, и в основном будет направлен на поддержку, а не на новые функции.



**Приоритет обновлений (примерно):**

Исправления сбоев >> исправления UX, влияющие на новых пользователей >> обновления функций > исправления UI и мелких ошибок.

<br/>

## Стратегия нумерации версий

Используется трёхзначный номер версии, например `1.80.3`.

**Первая цифра** (например, **1**.80.3) — номер версии для крупной переработки приложения; 1 — начальная официальная версия. При улучшениях возможны значительные изменения кода и редизайн UI.


**Средняя цифра** (например, 1.**80**.3) — номер функциональной версии. Увеличивается при выпуске функции среднего уровня или при накоплении относительно большого числа мелких функций.

Например:

> Версия 64 запустила систему Магазин и склад.
>
> Версия 70 запустила простой режим.
>
> Версия 80 запустила систему распаковки.



**Третья цифра** (например, 1.80.**3**) — номер ревизии для исправления проблем и сбоев после каждого функционального релиза. Также может приносить небольшие функции.


> В старых версиях третья часть номера обозначалась буквой, например 1.58c.
>
> Основная стратегия та же, но третья секция — буква, начиная с `a`.
>
> Однако некоторые магазины приложений не поддерживают такую схему, поэтому она отменена.
