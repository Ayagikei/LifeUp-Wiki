?> В версии v1.90 `LifeUp` открыл множество функциональных интерфейсов; интеграция с внешними приложениями приветствуется. <br/>Также доступен эффект «URL» для предметов Магазина: пользователи могут напрямую использовать товары для вызова внешних приложений или интерфейсов `LifeUp`. <br/>Эти функции открывают для вашего `LifeUp` безграничные возможности, но потребуют немного обучения и практики.

**Последнее обновление: 2026/08/28**

Параметры и определения API в этом документе основаны на версии **v1.106.0**.

Перед использованием последней версии API убедитесь, что приложение обновлено до **v1.106.0**.

Обновление постепенно распространяется через Google Play; если вы ещё не получили его, подождите — скоро оно придёт.

<br/>Иными словами, все перечисленные сценарии — это «события», которые запускают «действия».

В этом обновлении `LifeUp` добавлена точка срабатывания события «использование предмета», а также различные «действия» (Награды, выполнение Задач и т. д.).

Если вам нужны события вроде

- нажатия кнопки на веб-странице
- приложения NFC-карты
- первого разблокирования экрана после пробуждения каждый день

— потребуется участие внешних приложений: собственная доработка или инструменты автоматизации вроде `Tasker` и `MacroDroid`.

**Обновление LifeUp 1.90.2 добавит серию «событий», которые могут принимать инструменты автоматизации или внешние приложения.**

С их помощью можно, например:

После использования предмета запускать Tasker и другие инструменты автоматизации для смены обоев лаунчера.

После выполнения Задачи запускать Tasker и другие инструменты автоматизации для открытия приложения.

**В версии 1.90.2 можно реализовать срабатывание «операции Tasker» по «событию LifeUp».**

Tasker обладает очень широкими правами: смена обоев, удаление приложений, изменение громкости, выбор приложения для открытия и многое другое. Даже без основ программирования можно писать логику UI-взаимодействия.

**Если вы не знакомы с программированием,** найдите и импортируйте специальные предметы Магазина в [World] → [Market] → теги [Link]/[API]/[Automate]. Можно также отредактировать параметры под свои нужды.

**Если вы знакомы с компьютерами,** попробуйте прочитать документацию интерфейсов ниже и настроить нужный эффект самостоятельно. Даже без редактирования конфигурации Tasker достаточно установить Tasker, чтобы импортировать конфигурации автоматизации, которыми делятся на Market или в других сообществах.

**Если у вас есть основы программирования,** попробуйте разработать веб-страницы или Android-приложения для интеграции с LifeUp. Эта вики-страница и кастомные версии Wordle — примеры. Также приветствуется создание и публикация конфигураций инструментов автоматизации.

## Вызов других приложений

Чтобы вызвать внешнее приложение в *LifeUp*, добавьте предмету Магазина эффект «Link», **введите ссылку на веб-страницу или приложение** и используйте предмет для запуска вызова.

**Примеры (публичные предметы с эффектом вызова интерфейса также можно посмотреть в «World» → «Market» → «Link»):**

- Браузер открывает Google: https://www.google.com
- Facebook: [fb://](fb://)
- Открыть приложение по имени пакета / ID: [market://launch?id=net.sarasarasa.lifeup](market://launch?id=net.sarasarasa.lifeup)
- …

Теоретически, если внешнее приложение предоставляет URL, переход можно выполнить через предмет Магазина.

**Найдите нужную ссылку приложения, выполнив в Google поиск `URL Schemes`.**

**Эти ссылки не связаны с `LifeUp`; `LifeUp` лишь предоставляет функцию перехода по URL.**

**Поэтому мы не ведём и не поддерживаем список URL. Публичные предметы Магазина с эффектом ссылки можно посмотреть на странице [World] → [Market] → [Link].**

Имя пакета (ID) приложения можно узнать:

- в URL Google Play: https://play.google.com/store/apps/details?id=net.sarasarasa.lifeup
- через приложение-менеджер
- через действие App Info в Tasker
- через действие Launch App в MacroDroid

### Основы — экранирование (URL Encode)

Если значение параметра содержит специальные символы вроде +, пробела, =, %, &, # и т. д., его нужно экранировать:

| Спецсимвол | Значение                                         | Заменить на |
| :----------------- | :---------------------------------------------- | :--------- |
| +                  | Знак + в URL обозначает пробел        | +          |
| пробелы             | пробелы в URL могут быть + или закодированы              | %20        |
| /                  | разделяет каталог и подкаталог            | %2F        |
| ?                  | отделяет URL от параметров         | %3F        |
| %                  | указывает специальный символ                      | %          |
| #                  | означает закладку                                  | %23        |
| &                  | разделитель параметров в URL   | %26        |
| =                  | значение параметра в URL | %3D        |

На примере интерфейса всплывающего сообщения выше: если итоговый текст должен быть `You have learned to call APIs!`,
замените пробелы на + — результат:

<a href="lifeup://api/toast?text=You learned to call! &type=1&isLong=true">lifeup://api/toast?text=You learned to call! &type=1&isLong=true</a>

### Основы — ID данных LifeUp

Почти все данные в LifeUp имеют уникальный id.

Некоторые интерфейсы ниже поддерживают изменение **определённых** предметов Магазина и выполнение **определённых** Задач.

Чтобы `LifeUp` нашёл соответствующие данные, нужно передать id.

**Включите «Settings» → «Labs» → «Developer Mode», чтобы видеть исходный id данных на каждой странице деталей в приложении.**

Например, если атрибут отображается как «strength (1)», его attribute id равен 1.

#### Task id

Можно посмотреть на странице деталей события.

id: для повторяющейся Задачи id обновляется при каждом повторе.

gid: id группы элементов. Для одной и той же повторяющейся Задачи gid не меняется.

#### List id

После включения «Developer Mode» — во всплывающем окне «Select List».

#### Attribute id

После включения «Developer Mode» — на странице «Custom Attributes».

#### Shop item id

После включения «Developer Mode» нажмите на предмет Магазина, чтобы открыть детали.

#### Achievement condition id

После настройки условия разблокировки Достижения «requires an external API call to unlock» id условия виден на странице деталей.

<br/>

### Основы — сопоставление по имени

Если API поддерживает поиск Задач, предметов Магазина или подзадач по имени, LifeUp сначала пробует точное совпадение имени без учёта регистра. Если точного совпадения нет — нечёткое частичное совпадение.

Например, если есть «Coin» и «Coin Box», параметр `name=Coin` сначала совпадёт с «Coin», а не с тем нечётким результатом, который окажется раньше в списке.

При дублирующихся или похожих именах, которые могут быть неоднозначными, лучше передавать соответствующий id.

<br/>

### Основы — возвращаемые значения

Некоторые интерфейсы могут возвращать значения.

**При разработке Android-приложения** можно использовать метод `onActivityResult` для получения возвращаемого значения.

**При использовании приложения автоматизации вроде Tasker:**

Обычно такие приложения не могут получать возвращаемые значения типа Activity. Добавьте параметр `broadcast` и получайте возвращаемое значение через событие `received intent`.

Подробности см. в параметрах broadcast ниже.

### Основы — структура данных JSON

?> Требуется v1.98.0+

В этом разделе описаны часто используемые JSON-структуры в API.

#### 1. Item Reward Structure

JSON-массив, задающий Награды предметами; каждый элемент содержит ID и количество.

```json
[
    {
        "item_id": 1,    // Item ID
        "amount": 2      // Quantity
    },
    {
        "item_id": 2,
        "amount": 3
    }
]
```

#### 2. Achievement Unlock Condition Structure

```json
[
    {
        "type": 7,           // Condition type
        "related_id": null,  // Related ID (some types must provide)
        "target": 1000000    // Target value
    }
]
```

#### 3. Purchase Limit Structure

`purchase_limit` — JSON-массив. Каждый объект — одно правило ограничения.

| Поле | Значение | Тип | Обязательно | Примечания |
| ----- | ------- | ---- | -------- | ----- |
| limitType | Тип ограничения | number | Да | См. таблицу типов ниже |
| limitNumber | Основное числовое значение | number | Нет* | Для правил по количеству / диапазону |
| maxNumber | Верхняя граница диапазона | number | Нет | Для диапазона уровня Атрибута / количества предметов в Инвентаре |
| limitId | ID связанной цели | number | Нет* | Обязателен для правил по Атрибутам / предметам / Задачам / циклу Задач / Достижениям |
| extendInfo | Дополнительные данные | string | Нет | Для правил по времени; само значение — JSON-строка |

**Определения типов**

| limitType | Значение | Обязательные поля / примечания |
| --------- | ------- | ----------------------- |
| 0 | Дневной лимит количества | `limitNumber`: макс. раз в день |
| 1 | Недельный лимит количества | `limitNumber`: макс. раз в неделю |

#### Настройка эффекта Лутбокса

**Имя метода:** loot_box

**Описание:** Изменить эффект Лутбокса указанного предмета-сундука: вероятность, количество наград и добавление содержимого. (Удаление пока не поддерживается)

**Пример:** <a href="lifeup://api/loot_box?name=Coin loot box&sub_name=A big bag of coins&set_type=relative&probability=1&fixed=false">lifeup://api/loot_box?name=Coin loot box&sub_name=A big bag of coins&set_type=relative&probability=1&fixed=false</a>

**Пояснение:** Увеличить долю [большого] мешка золотых монет в золотом сундуке на 1 пункт.

| Параметр   | Значение                               | Тип                                                    | Пример        | Обязательно | Примечания                                                        |
| ----------- | ------------------------------------- | ------------------------------------------------------- | -------------- | -------- | ------------------------------------------------------------ |
| id          | id предмета                               | число больше 0                                 | 1              | нет*      | Как получить ID — см. выше «Основы — ID данных LifeUp» |
| name        | имя предмета                             | любой текст                                                | Treasure chest | нет*      | При неизвестном id — нечёткий поиск предмета, не переименование |
| sub_id      | id предмета-содержимого                       | число больше 0                                 | 1              | нет*      | id содержимого сундука                                         |
| sub_name    | имя предмета-содержимого                     | любой текст                                                | Get a gift     | нет*      | Нечёткий поиск предметов, когда id содержимого сундука неизвестен |
| set_type    | способ изменения (absolute/relative) | одно из следующих значений: <br/>absolute<br/>relative | relative       | нет       | absolute — абсолютное значение, то есть установить цель в value<br/>relative — относительное значение, прибавить или вычесть от исходного |
| amount      | количество предмета-содержимого                | number                                                  | 1              | нет       | количество наград одного предмета                          |
| probability | вероятность предмета-содержимого       | number                                                  | 1              | нет       | -                                                            |
| fixed       | фиксированная ли награда          | boolean                                                 | true/false     | нет       | -                                                            |

**Примечание:**

1. Для поиска предмета нужно передать id или name.
1. Для поиска содержимого нужно передать sub_id или sub_name.
1. `name` и `sub_name` сначала ищутся по точному совпадению, затем по нечёткому.
1. Устаревший API `loot_box` сохраняет поведение совместимости: если один и тот же предмет встречается несколько раз с разным количеством, редактируется первая найденная запись, `sub_amount` для различения не используется. Используйте `loot_box/v2`, если нужно редактирование, удаление или слияние по конкретному количеству.

**Описание:** Улучшенная версия API loot_box. Изменить эффект Лутбокса указанного предмета-сундука: вероятность, количество наград, добавление содержимого и **удаление содержимого**.

**Улучшения по сравнению с v1:**
- **`sub_amount` для точного сопоставления**: если в сундуке несколько записей одного предмета с разным количеством (напр. A x1 50%, A x2 30%), используйте `sub_amount`, чтобы выбрать конкретную запись. Значение по умолчанию — `1`. Если совпадение не найдено, LifeUp ищет предмет по `sub_id` / `sub_name` и добавляет новую запись; при запросе на удаление с `amount=0` новая запись не добавляется.
- **Независимый `set_type`**: `amount_set_type` и `probability_set_type` управляются отдельно. Глобальный `set_type` используется как запасной по умолчанию.
- **Поддержка удаления**: `amount=0` с `amount_set_type=absolute` (или результат `<=0` при `relative`) удаляет найденную запись.
- **Слияние дубликатов**: если изменение `amount` создаст дубликат существующей записи с тем же предметом и количеством в том же сундуке, LifeUp объединяет записи и продолжает применять `probability` / `fixed` из запроса.

**Пример:** <a href="lifeup://api/loot_box/v2?name=Coin loot box&sub_name=A big bag of coins&sub_amount=2&probability_set_type=relative&probability=10">lifeup://api/loot_box/v2?name=Coin loot box&sub_name=A big bag of coins&sub_amount=2&probability_set_type=relative&probability=10</a>

**Пояснение:** Увеличить вероятность [большого] мешка золотых монет (x2) в золотом сундуке на 10 пунктов.

| Параметр              | Значение                               | Тип                                                    | Пример        | Обязательно | Примечания                                                        |
| ---------------------- | ------------------------------------- | ------------------------------------------------------- | -------------- | -------- | ------------------------------------------------------------ |
| id                     | id предмета                               | число больше 0                                 | 1              | нет*      | Как получить ID — см. выше «Основы — ID данных LifeUp» |

**Примечание:**

1. Для поиска предмета нужно передать id или name.
1. Для поиска содержимого нужно передать sub_id или sub_name. Используйте `query=true`, чтобы вывести содержимое без sub_id / sub_name.
1. Если переданы и `sub_id`, и `sub_name`, приоритет у `sub_id`. `sub_name` используется только когда нет корректного `sub_id`.
1. `name` и `sub_name` сначала ищутся по точному совпадению, затем по нечёткому.
1. `sub_amount` по умолчанию `1`. Если в сундуке несколько записей одного предмета с разным количеством, укажите `sub_amount`, чтобы выбрать конкретную запись. Если совпадение не найдено и это не запрос на удаление, добавляется новая запись с `amount=sub_amount`.
1. Чтобы удалить запись, задайте `amount=0` с `amount_set_type=absolute` или используйте `amount_set_type=relative` с отрицательным значением, которое даёт итог `<=0`. Удаление применяется только к найденным записям; если совпадение не найдено, `amount=0` не добавляет новую запись.
1. Если изменение `amount` создаст дубликат существующей записи с тем же предметом и количеством в том же сундуке, LifeUp объединяет записи и продолжает применять `probability` / `fixed` из запроса.
1. Если после удаления сундук становится пустым, весь эффект Лутбокса мягко удаляется (сам предмет сохраняется, записи Лутбокса можно добавить снова позже).

### Таймер Pomodoro

**Имя метода:** pomodoro_timer

**Описание:** Управление реальным обратным отсчётом Pomodoro или таймером нарастающего времени в LifeUp. Этот API запускает
ту же сессию таймера, что и интерфейс App; он не добавляет напрямую записи Pomodoro или помидоры.

**Примеры:**

- Запустить или возобновить обратный отсчёт работы по умолчанию:
  [lifeup://api/pomodoro_timer?action=start&mode=countdown](lifeup://api/pomodoro_timer?action=start&mode=countdown)
- Запустить таймер нарастающего времени и выбрать Задачу 101:
  [lifeup://api/pomodoro_timer?action=start&mode=count_up&task_id=101](lifeup://api/pomodoro_timer?action=start&mode=count_up&task_id=101)
- Приостановить активный обратный отсчёт:
  [lifeup://api/pomodoro_timer?action=pause&mode=countdown](lifeup://api/pomodoro_timer?action=pause&mode=countdown)
- Прервать и сбросить цикл Pomodoro:
  [lifeup://api/pomodoro_timer?action=abandon&mode=countdown](lifeup://api/pomodoro_timer?action=abandon&mode=countdown)
- Пропустить текущий этап Pomodoro:
  [lifeup://api/pomodoro_timer?action=skip](lifeup://api/pomodoro_timer?action=skip)
- Завершить таймер нарастающего времени без награды помидорами:
  [lifeup://api/pomodoro_timer?action=complete&mode=count_up&receive_reward=false](lifeup://api/pomodoro_timer?action=complete&mode=count_up&receive_reward=false)
- Запросить оба режима таймера:
  [lifeup://api/pomodoro_timer?action=status](lifeup://api/pomodoro_timer?action=status)

**Параметры:**

| Параметр | Значение | Тип / значения | Обязательно | Примечания |
| --------- | ------- | ------------- | -------- | ----- |
| action | операция | `start`, `pause`, `abandon`, `skip`, `complete`, `select_task`, `status` | да | - |
| mode | режим таймера | `countdown`, `count_up` | для `start`, `pause`, `abandon` и `complete` | `skip` всегда относится к обратному отсчёту. |
| stage | этап обратного отсчёта | `work`, `short_break`, `long_break` | нет | Только при `mode=countdown`. Если не указан, используется активный, приостановленный или следующий канонический этап; новый цикл начинается с `work`. |
| receive_reward | получать ли награду помидорами | `true` или `false` | для `complete` | Строгое boolean. `complete` поддерживает только `mode=count_up`. |
| task_id | ID Задачи | положительное целое число | нет | Нельзя сочетать с `task_gid` или `task_name`. |
| task_gid | ID группы Задач | положительное целое число | нет | Можно сочетать с `task_name`, чтобы сузить поиск. |
| task_name | имя Задачи | text | нет | Сначала точное совпадение, затем нечёткий поиск. |
| clear_task | очистить Задачу таймера | `true` или `false` | нет | `true` нельзя сочетать с указателем Задачи. |

`select_task` требует указатель Задачи или `clear_task=true`. `start` может включать те же
параметры выбора Задачи. Пользовательская длительность не поддерживается: обратный отсчёт использует
текущую длительность по умолчанию или длительность Pomodoro выбранной Задачи.

`abandon&mode=countdown` эквивалентно левому действию в App: отменяет текущий этап,
сбрасывает цикл Pomodoro и возвращает к остановленному этапу `work`. `skip` эквивалентно
правому действию: переводит work в короткий/длинный перерыв или перерыв в work, не запуская
следующий этап автоматически. Каждый вызов `skip` — реальное неидемпотентное действие; вызывающая сторона не должна
повторять его автоматически.

`complete&mode=count_up` завершает реальную сессию нарастающего времени. Сессии короче 30 секунд
завершаются без создания записи. При `receive_reward=false` запись, которая проходит порог,
всё равно сохраняется как прерванная, но помидоры не начисляются.

**Правила смены Задачи:**

- Активный обратный отсчёт work отклоняет смену Задачи.
- Активный таймер нарастающего времени позволяет менять Задачу и обновляет уведомление.
- Приостановленный обратный отсчёт позволяет менять Задачу, сохраняет прошедшее время и пересчитывает общую
  длительность по настройкам новой Задачи.

**Успешные возвращаемые значения:**

| Параметр | Значение | Тип |
| --------- | ------- | ---- |
| api_result | успешен ли вызов API | boolean |
| applied | изменило ли это обращение состояние таймера | boolean |
| mode | целевой или текущий выбранный режим таймера | `countdown` или `count_up` |
| state | состояние `mode` | `running`, `paused` или `stopped` |
| selected_task_id | текущий ID Задачи таймера или `0` | number |
| can_start_in_background | разрешает ли Android сейчас запуск таймера в фоне | boolean |
| countdown_state | каноническое состояние обратного отсчёта | `running`, `paused` или `stopped` |
| countdown_phase | фаза жизненного цикла обратного отсчёта | `idle`, `running`, `paused`, `completing`, `completed` или `cancelled` |
| countdown_stage | канонический этап обратного отсчёта | `work`, `short_break` или `long_break` |
| countdown_session_id | канонический ID сессии обратного отсчёта | text или null |
| countdown_total_millis | общая длительность обратного отсчёта | milliseconds |
| countdown_remaining_millis | оставшаяся длительность обратного отсчёта | milliseconds |
| count_up_state | каноническое состояние нарастающего времени | `running`, `paused` или `stopped` |
| count_up_elapsed_millis | прошедшая длительность нарастающего времени | milliseconds |
| battery_optimization_ignored | освобождён ли LifeUp от оптимизации батареи | boolean |

Успешные ответы `complete` дополнительно содержат `record_created`, `reward_tomatoes` и
`settled_elapsed_millis`.

Повторные вызовы `start`, `pause` или `abandon`, когда состояние уже соответствует запросу, завершаются успешно с
`applied=false`. Изменяющие вызовы не обеспечивают межпроцессную дедупликацию повторов.

**Ошибки:**

При ошибке возвращаются `api_result=false`, `error_code` и `error_message`. Стабильные коды ошибок,
специфичные для таймера:

- `invalid_parameter`
- `missing_required_parameter`
- `unsupported_action_for_mode`
- `task_not_found`
- `task_change_not_allowed`
- `timer_mode_locked`
- `timer_state_conflict`
- `background_start_not_allowed`
- `timer_start_failed`
- `timer_settlement_failed`

На Android 12 и новее фоновый вызов ContentProvider может запустить таймер только когда LifeUp
может игнорировать оптимизацию батареи. Иначе возвращается `background_start_not_allowed`
до изменения состояния таймера. Открытие URL Scheme через Activity выводит LifeUp на
передний план перед запуском. Android может заблокировать запуск этой Activity сторонним приложением из
фона; в этом случае LifeUp не получает вызов API и не может вернуть ошибку.

| Параметр        | Значение                    | Тип                    | Пример       | Обязательно | Примечания |

| start_time       | время начала тайминга          | timestamp               | 1659322800000 | нет*      | Если не знаете, что такое Timestamp — поищите в Google! |

1. Нужно указать один из start_time, duration, end_time.
2. Если указан только duration, end_time по умолчанию — текущее время.

5. Если указаны start_time, duration и end_time, duration должно быть меньше или равно (end_time - start_time).

?> Этот API добавлен в v1.105.1.

**Описание:** Завершить ручное Достижение и получить Награду или получить Награду уже разблокированного автоматического Достижения. То же поведение, что при нажатии флажка завершения / кнопки получения Награды в App.

> - Существующие Достижения с `type=520` сохраняют семантику разных Задач; миграция не требуется.

#### Callback по завершении

К любому интерфейсу можно добавить параметр callback, чтобы после вызова выполнить обратный вызов URL.

Это также позволяет объединять несколько интерфейсов — например, показать подсказку после перехода:

lifeup://api/goto?page=lab + lifeup://api/toast?text=callback

Используйте параметр callback. См. также выше **Основы — экранирование (URL Encode)**. Можно написать так:

<a href="lifeup://api/goto?page=lab&callback=lifeup:%2F%2Fapi%2Ftoast%3Ftext%3Dtest callback">lifeup://api/goto?page=lab&callback=lifeup:%2F%2Fapi%2Ftoast%3Ftext%3Dtest callback</a>

Конечно, можно добавить несколько ссылок к Предмету Магазина, чтобы добиться этого эффекта.

Кроме того, этот callback чаще используется для:

X-приложение → LifeUp → X-приложение

или

X-приложение → LifeUp → Y-приложение

#### Возвращаемое значение через broadcast

!> Функции здесь предназначены для инструментов автоматизации и вторичной разработки и имеют определённый порог входа.

Добавив этот параметр, исходное возвращаемое значение API также можно отправить через broadcast — чтобы Tasker и другие инструменты автоматизации могли его получить.

Значение broadcast эквивалентно значению столбца «действие» в «Intent Received» в Tasker. Можно указать любой текст — главное, чтобы они совпадали.

**Например, API запроса монет с Tasker ([если используете MacroDroid, см. эту ссылку.](https://github.com/Ayagikei/LifeUp/issues/43)):**

[lifeup://api/query?key=coin](lifeup://api/query?key=coin)

1. Добавьте параметр broadcast, чтобы отправлять возвращаемое значение в Tasker — любой текст, например `app.lifeup.query.coin`.

   [lifeup://api/query?key=coin&broadcast=app.lifeup.query.coin](lifeup://api/query?key=coin&broadcast=app.lifeup.query.coin)

2. В Tasker добавьте событие → «Intent Received», в столбце action укажите `app.lifeup.query.coin`

3. Задача в Tasker получит возвращаемое значение `value` в виде переменной `%value`.

4. Затем в Tasker можно проверять количество монет для разных эффектов. (Например, менять обои рабочего стола в зависимости от количества монет?)

### Пример: смена обоев с помощью Предмета

1. Создайте новый Предмет «Change Wallpaper».
2. В Tasker: `Configuration file` → `Event` → `System` → `Intent Received`, в столбце operation укажите `app.lifeup.item.use` и вернитесь.
3. Нажмите New Task и введите любое имя (например, change wallpaper).
4. Нажмите + в правом нижнем углу, добавьте задачу, выберите `Task` → `If`
5. В столбце условия установите `%name eq change wallpaper`.
6. Вернитесь, `Insert Action`, выберите `If`.
7. Снова нажмите +, добавьте задачу, выберите `Display` → `Set Wallpaper`
8. (Необязательно) Замените `Type` на `All`
9. В столбце image нажмите 🔍 и выберите нужный файл обоев
10. Выйдите и проверьте, что конфигурация включена.
11. Используйте Предмет «Wallpaper Change» в `LifeUp` — обои должны смениться

### Жизненный цикл Pomodoro

?> Это broadcast-событие добавлено в v1.101.0 и предоставляет более подробные данные о событиях.

**Name:**

- Start: app.lifeup.pomodoro.start

**Описание:** Когда таймер Pomodoro запускается, ставится на паузу, останавливается или завершается, система отправляет соответствующие broadcast-события с информацией о Задаче, статусом тайминга и другими данными.

**Возвращаемое значение:**

| Параметр          | Значение                       | Пример        | Примечания                                                      |
| ------------------ | ----------------------------- | -------------- | ---------------------------------------------------------- |
| task_id            | ID Задачи                       | 1              | Необязательно, только если Pomodoro связан с Задачей |
| task_gid           | ID группы Задач                 | 1              | Необязательно, только если Pomodoro связан с Задачей |
| name               | имя Задачи                     | Study English  | Имя Задачи, связанной с Pomodoro, или пользовательское имя         |

##### Без SDK

```kotlin
    /**
    * Define a method to handle the uri
    */
    private fun call(context: Context, uriString: String){
        try {
            val intent = Intent(Intent.ACTION_VIEW).apply {
                data = Uri.parse(uriString)
            }
            context.startActivity(intent)
        }catch (e: Exception) {
            e.printStackTrace()
        }
    }

fun xxx() {
        ...
        // Then call it where appropriate
        call(context, "lifeup://api/toast?text=You+learned+to+call!&type=1&isLong=true")
        ...
    }
````

#### Веб-страница

При вызове с веб-страницы результат зависит от браузера. Обычные браузеры вроде Quark, Chrome и Edge работают нормально. Но некоторые встроенные системные браузеры могут каждый раз спрашивать пользователя «открыть Rensheng».

Если вы разрабатываете собственное приложение с встроенным WebView, убедитесь, что WebView обрабатывает схему lifeup.

Для единообразного опыта можно использовать эффект ссылки на Предмет в `LifeUp` и включить «Use built-in browser». Из соображений безопасности этот способ поддерживает только HTTPS-ссылки (не HTTP).

**HTML**

Прямой переход по гиперссылке

````htm
<a href="lifeup://api/toast?text=You learned to call!&type=1&isLong=true" target="_blank" rel="noopener">Click here to call</a>
````

**Javascript**
